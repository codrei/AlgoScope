Problem

The narration module (say.ts) is shallow: interp.ts and builtins.ts format strings into transient fields, and say.ts, analysis.ts, and Visualizer.tsx re-parse those strings with 35+ regexes across the seam.

Solution

Replace string notes and regex parsers with a deep StepRecorder module that accepts structured events, resolves event priority internally, and emits both narrations plus typed metadata on Step.

Wins

  • Locality: one module owns narration
  • Delete 35+ cross-file regexes
  • Leverage: typed Step metadata
  • Tests hit one clean interface

Problem

Solution

Deepen runtime containers so mutations automatically record touches, counts, and version bumps, pass evaluated values across the builtins.ts seam, and pass object-formatting context explicitly.

Wins

  • Delete fake __val AST nodes
  • Remove global objTextHook state
  • Interface shrinks between engine modules

Problem

Language front-ends encode closures, C++ member initializers, and C# properties as fake calls (__closure__, __fieldinit__) and mangled keys (lambda@12:4, __get_X) in Program, forcing index.ts, suggest.ts, and interp.ts to filter magic strings.

Solution

Represent statement/expression closures, property getters, and field initializers as explicit ir.ts constructs and consolidate duplicated enum/lambda/array-init lowering in lower/util.ts.

Wins

  • Stop leaking @ / __ across IR seam
  • Locality: one closure mechanism in Interp
  • Deduplicate Java/C# lowering helpers

5. Single-pass entry suggestion and typed IR visitor

Speculative in-process
src/engine/index.ts src/engine/suggest.ts src/engine/lower/util.ts
Before · Double lowering & untyped AST reflection
1. runCode() calls lower*(root, true)
2. Throws CompileError("No main()")
3. Catch block re-runs lower*(root, false) from scratch
4. suggest.ts walks IR via untyped Object.values(stmt) reflection
After · Single lowering pass & shared IR visitor
1. Single-pass lower*(root) → Program
Returns Program with optional entry
2. Shared walkIR(stmts, visitor)
Reused by collectIndexVars, callsIn, and returnsValue

Problem

When a student's code has no main(), runCode throws inside lowering and lowers the syntax tree a second time in the catch block, while suggest.ts inspects IR nodes using fragile Object.values reflection.

Solution

Make lower* always return Program so runCode handles missing prog.entry in one pass, and extract a single typed IR visitor shared by util.ts and suggest.ts.

Wins

  • Delete requireEntry parameter
  • Locality: one typed IR walker
  • Eliminates double AST lowering
